Secrets: values live ONLY in `.env` (gitignored). Repo is PUBLIC — never commit keys.

## 1. COMPONENT ARCHITECTURE

**Stack:** Static site on GitHub Pages (repo `Lordner-Visual/ACBreakz`, branch `master`, push = deploy ~30-60s) · Supabase `jqowngdkgnfhaworyppo` (Postgres+Realtime+Storage bucket `media` + 3 edge functions, Deno) · fal.ai (FLUX images, stable-audio, Kling video) · Stream Deck profiles generated by Node scripts · Playwright QA (`node qa/shoot-*.mjs`).

**Topology:** 5 independent stream PCs. Each: OBS scene `ACBreakz Cloud N` with 3 browser sources `overlay/?layer=bg|hud|fx&pc=N` (1080×1920@60). Per-PC state = `stream_state` rows id 1..5. Master panel `control/` (password→30-day token). Per-PC dashboard `control/pc.html?pc=N` (no login, OP_KEY in `control/op.js`, state+events+composer only). Stream Deck = API Ninja GET → `/deck`. Writes: panel/pc/deck → edge fn (service role) → `stream_state` UPDATE + `events` INSERT → realtime → overlays. Overlay self-updates (45s no-store hash poll → reload); only `layer=fx` plays audio.

```js
  animStyle:assetRow|null,            // team-anim style; null→Classic per-team webms

  oneshots:{"<deck name>":assetId},   // per-PC choice for each Stream Deck event key
  updatedAt:ms, lastWriter:"deck"|clientId|"server" }   // both stamped SERVER-SIDE by state_stamp()
```
**assets** (kind ∈ background|banner|animation|sfx|logo|style; url; meta jsonb):
`{type:upload|ai|text, text, prompt, team:abbr, group:team|oneshot, image:bool, domain:team_anim|board_button|board_bg|button_anim, base_url,button_url,bg_url,poster, effect:none|glow|fire|lightning|glitch|pop, mode:ambient|trigger, per_team, builtin, sfxUrl,sfxName ("sfxUrl" in meta = linked; null = No SoundFX beats default), crop:{x,y,z(100-600)}, fit:"full"|"box", template, hideComposer, hideRotation, deleted, deletedAt}`

**/deck** GET `?key=DECK_KEY&action=X[&pc=N]` (no pc = all 5; deployed `--no-verify-jwt`): `team_toggle` (server reads board → pick|restore; THE deck key action), `team_pick`, `team_restore`, `board_reset`, `highlight|unhighlight|highlight_toggle|highlight_clear` (highlight NEVER restores a team — independent of elimination), `play&name=` (per-PC `oneshots[name]` if set, else ilike newest; boxed unless meta.fit==="full"), `play_loop&name=` (TOGGLE via loop_fx_toggle() row lock → data.loopFx; same clip stops it, a different clip switches), `banner_skip`, `set_background&name=`. `board_mode|board_visible` = retired no-ops.

**/panel** POST auth: `{action:"login",password}→{token}` | `{token}` | `{key:PANEL_KEY}` (scripts) | `{op:OP_KEY,pc:1-5}` (operator: only state/event/sign_upload `^banners\/composed-`/asset kind=banner non-template). Actions: `patch{pc,clientId,patch}` (non-board keys, atomic), `board{pc,clientId,boardAction,team}` (atomic board_action), `state{pc,data,force?}` (legacy whole-doc — board-protected unless force), `event{pc,type,payload}`, `asset{asset}`, `update_asset{id,meta}` (merge; sweeps rotation copies+bg crop; hideRotation⇒deselect), `delete_asset` (soft→trash+deselectEverywhere), `restore_asset` (clears deleted+both hide flags), `purge_asset`/`empty_trash` (remove files+rows+deselect), `sign_upload{path}`→`uploadToSignedUrl`.

**/generate-asset** POST `{key, kind, prompt, quality:"standard"|"best", mode:"inline"|"submit"|"poll", request_id, model, status_url, response_url, no_row, as:{kind,name,meta}, brand:bool, ref_url, longer:bool}`. Kinds: images(background,banner,animation_still,board_button:1024²,board_bg:1344×384) inline FLUX (`ref_url`→flux/dev/image-to-image, strength .65); `sfx`→stable-audio (queue, 1-4min); video(background_anim,board_bg_anim,button_anim)→Kling 1.6 std $0.25 / v2 master $1.40 (queue; `ref_url`→image-to-video). Loop clips duration "5"+perfect-loop prompt; `longer:true`→"10" no loop (one-shots). NO auto-branding — BRAND prefix only when `brand:true`. Poll uses `status_url/response_url` FROM SUBMIT RESPONSE.

Mgmt API SQL (schema changes): `POST https://api.supabase.com/v1/projects/jqowngdkgnfhaworyppo/database/query` with Bearer SUPABASE_ACCESS_TOKEN, `{query:"…"}`.

## 4. ACCUMULATED NUANCES & NEVER-DO RULES

- **VP9 alpha is side-channel**: ffprobe says `yuv420p` even with alpha. Decode `-c:v libvpx-vp9` (input opt), encode `-pix_fmt yuva420p -auto-alt-ref 0`, fade `fade=t=out:…:alpha=1`. M3 lost alpha this way (black bg bug). Current stingers `animations/v2/`, cropped one-shots `animations/v4/`; old flat files unreferenced.
- **API Ninja**: empty-string file fields → NullReference in `LoadHeadersAndUserData` → EVERY request dies (⚠). Must be `"No file..."`. `autorunMinutes:"0"` = fire-every-0-min crash loop; empty = off. Multi Action ✓ ≠ plugin success. Its plugin manifest is ENCRYPTED — read `PropertyInspector/*.html/js`, the DLL strings, or diff a hand-made exported button (fastest, do this FIRST next time).
- **Stream Deck**: profiles live in `ProfilesV3` (not V2). Import DUPLICATES (delete old first). PowerShell/.NET zip writes backslash entries → silent import failure. `PageIndex` 1-based. `system.open` = files only; URLs need `system.website` `{openInBrowser:true,path}`. Icons are per-key press-state only (can't track board; accepted cosmetic drift). Icon art: `streamdeck/icons/*`.
- **Write model (V11 — replaces the old "echo clock" rule)**: `data.board` is written ONLY by `board_action()`; every other top-level key ONLY by `state_patch()`/`state_replace()` (`supabase/migrate-v11-atomic.sql`, applied). All three `select … for update` the row and lock PCs in ASCENDING id order (deadlock-free). That row lock IS the queue — an app-level queue was rejected: a dead worker returns 200 for a press that never applied. NEVER do I/O while holding the lock — the edge fns pre-resolve stinger/sfx assets and pass them as `p_fx`. The FX event inserts in the SAME transaction and only on a real transition, so a stinger cannot play for an elimination that did not record (pre-fix, measured: 12 stingers fired, 1 recorded; 12 simultaneous presses landed 1). `updatedAt`/`lastWriter` are stamped in ONE place (`state_stamp`, Postgres `clock_timestamp()`); pages suppress their own echo by `lastWriter === CLIENT_ID` and drop out-of-order realtime by `updatedAt < current` — that comparison is valid ONLY because of the single clock; the old browser-vs-edge one silently dropped real writes and then re-pushed over them. Each page keeps ONE write in flight and coalesces pending patches (concurrent same-key patches otherwise land out of order). Anon must stay denied on all three RPCs (grants are service_role only). `qa/shoot-concurrency.mjs` + `qa/shoot-panel-race.mjs` guard it; the old "panel writes first, 1.2-1.5s apart" QA rule is retired.
- **Write model (V13 — the asset writers)**: `deselectEverywhere` and `update_asset` propagation were the last read-whole-doc→write-whole-doc writers, and they were NOT harmless: reached by delete/purge/empty_trash/hideRotation and the Reframe **Save crop** button — all routine mid-show actions — each read five rows and wrote them back unlocked, erasing any press that landed mid-loop *after* the API had returned OK and the stinger had played. Now `assets_deselect()` / `assets_propagate_meta()` (`supabase/migrate-v13-asset-writes.sql`, applied): loop `1..5 order by id`, `select … for update`, and mutate ONLY `banners.rotation`/`background`/`animStyle`/`boardButtons`/`boardBg`/`buttonAnim`/`buttonAnims` via `jsonb_set` — being field-scoped makes them structurally incapable of touching `board`, `loopFx` or `oneshots`. Rotation order is preserved with `with ordinality`. **Five decks pressed at once were always safe** (separate rows, separate locks); it was master-panel asset work that broke them. `qa/shoot-multipc.mjs` proves it — and note a race test that fires ONCE proves nothing: its first run passed, and only starting the sweep first and repeating 8 rounds exposed the bug (lost in 8/8).
- **Never hold a lock for housekeeping**: `board_action`'s inserts into `events`/`deck_log` used to fire statement triggers that DELETEd expired rows — which are GLOBAL, not per-PC — so a five-PC master tap and a single-PC deck press could deadlock. Triggers dropped; the deck fn calls `prune_now()` opportunistically (~2% of calls) AFTER the RPC returns, unawaited via `EdgeRuntime.waitUntil`. It must `returns int`, never `returns void`: PostgREST answers a void RPC with **204 + empty body**, which `.json()` throws on outside the `.catch()` — measured 4/200 deck calls failing until it returned a value (0/250 after).
- **Restart ≠ rebuild**: to restart a playing `<video>`, SEEK it (`currentTime=0;play()`). Removing/recreating the element drops to readyState 0 → blank frame until re-buffer + one refetch per cell per change (v10 bug: "any change kills the button animations" — only bit the AI-clip path, CSS builtins restart free, so v9's acceptance missed it). New elements need `autoplay:true` — no blanket play() loop exists anymore. QA that frame-samples races the CDN cache and can pass on broken code; assert on element identity (dataset tags surviving) + refetch counts instead.
- **Master/PC list parity**: any list rendered in BOTH `control/index.html` and `control/pc.html` must use the IDENTICAL filter — the dashboards have no delete, so anything they list that master doesn't is unremovable (pc.html listed `kind:"background"` as composer art long after master narrowed to banner-only ⇒ 9 undeletable cards). Composer membership = `inComposer()` in master: `url && kind==="banner" && meta.type!=="text"`, minus `hideComposer`. These lists derive from the shared `assets` row, NOT per-PC state — there is nothing to migrate, fixing the predicate syncs all five instantly. `qa/shoot-composer-sync.mjs` guards it.
- **Deletion**: every removal path (delete/purge/empty_trash/hideRotation) MUST `deselectEverywhere` or OBS shows blank frames. Rotator also skips missing files via `onerror`. Purge is REFERENCE-COUNTED (`unreferencedFiles` in panel fn): "file into section" makes a second row pointing at the SAME storage file, so a file is only removed when no surviving row's url/base_url/button_url/bg_url/poster/sfxUrl points at it — before this, purging the original deleted the file under the filed copy (lost 2 AI clips 2026-08-11). `qa/shoot-purge-refs.mjs` proves it; judge storage existence by BUCKET LISTING, the public URL serves CDN-cached 200s long after deletion (also why a dead file can keep "working" in an open overlay).
- **Cold start is the "it didn't play the first time" bug**: nothing preloaded FX media and the overlay doesn't even learn a stinger URL until the press event arrives, so a first press was a cold fetch of a ~6 MB clip (205 MB for the set, and `upload-v2.mjs` never set `Cache-Control`, so it was served `no-cache`). Which teams "showed" tracked purely which clips happened to be cache-warm — that is the same bug as "sound plays, stinger doesn't, for some teams only". The overlay now warms the resolved set on load and whenever `animStyle.meta.set`/`oneshots` change, via throwaway `<video preload=auto>` elements it then removes (bytes stay in the HTTP cache, decoders do not). Two non-optional constraints: **gate on `layer==="fx"||"all"`** (each PC runs three browser sources — ungated, every PC pulls the set 3× = 615 MB) and **cap concurrency at 3** (32 parallel 6 MB fetches at OBS start spike the same uplink the stream goes out on). New uploads set `cacheControl:"31536000"`. `qa/shoot-fx-warm.mjs` asserts 30+ clips on `layer=fx` and exactly 0 on `layer=hud` — and its two counting passes `route()`+`abort()` the clip bodies, because they only ever needed the URLs and were costing ~250 MB of real egress per run. The warmed bytes DO survive a reload (measured 239 MB cold -> 0 MB on reload) but only because those clips are under the browser's cache-size cliff; see the egress rules below.
- **`playVideo` must be able to give up**: it used to exit only on `ended`/`error`/rejected `play()`, so a hung buffer pinned `fxBusy` and wedged the whole FX queue until reload. It now has an 8s watchdog, and on a rejected `play()` it retries MUTED — the graphic matters more than its audio, and team stingers are `-an` but the game one-shots carry Opus. QA cannot catch that path: Playwright runs with `--autoplay-policy=no-user-gesture-required`.
- **Realtime delivers the state row BEFORE its event**: `board_action` writes `stream_state` and inserts `events` in ONE transaction, and the row always arrives first (measured ~630ms vs ~700ms). So anything the event handler wants to choreograph must be deferred by `applyState`, not by the handler — parking the team in `pendingDim` from `handleEvent` was always too late, the cell had already been painted. `applyState` now parks any not-out→out transition itself and arms a 900ms fallback; `team_pick` takes that fallback over and re-arms 1200ms from the video's `playing` event (2600ms cap), so the board never dims before the stinger exists. `boardBooted` keeps the FIRST paint immediate — a page load is not a transition. Restores/resets must `clearDim` every timer the team is owed, and must NOT re-run `applyState` from the handler: `lastState` still says the team is out, so it would arm a fresh dim for the team just put back.
- **A dangling reference is invisible until you look for it**: `assets_deselect` only runs when a row is deleted THROUGH the panel, so a row purged before V13 (or by a direct DB edit) leaves its entry alive inside every PC's `banners.rotation`/selection with no row left to clean up. One such orphan — a banner whose row was hard-purged in the pre-reference-counting era — sat in all five rotations and generated **~330 HTTP 400s an hour, 8,765 in 48h, 87% of ALL Supabase requests**, for weeks, in complete silence. `scripts/audit-refs.mjs` is the detector: it cross-checks every url/base_url/button_url/bg_url/poster/sfxUrl on every asset row AND every per-PC selection against the BUCKET LISTING (never the public URL — the CDN serves cached 200s long after a delete), exits non-zero on findings, and `--fix` deselects through the row-locked `assets_deselect`. Run it after any purge and whenever something "works but shouldn't". It is also how you check the backlog's "dead asset" claims instead of trusting them.
- **Never re-ask for media that already failed**: the rotator keeps a `deadMedia` Set and skips a known-bad url WITHOUT building an element, so a dangling reference costs ONE request per session instead of one per rotation cycle per source, forever. A replaced file always arrives under a new timestamped url, so nothing legitimate is blocked, and a reload clears the set anyway. `qa/shoot-banner-slide.mjs` asserts the dead url is requested at most once.
- **Never destructure only `data` from a PostgREST call**: every lookup in the deck fn did `const { data } = await q`, dropping `error`. PostgREST returned a transient **401 to the service-role client 16 times in 48h**, and each one made `teamClipUrl` return null — so the press eliminated the team and played its sfx with NO stinger. That is indistinguishable from a missing clip, which is exactly why it hid behind the cold-media bug for so long. All five lookups now go through `q1()`: retry once, then `console.error` loudly so it lands in the function logs. Check `function_edge_logs`/`edge_logs` for 401s when a stinger "sometimes" does not play.
- **Audio**: keep `Audio` refs in a Set until ended (GC aborts request); only `layer=fx`/`all` plays sound — "sound but no stinger" ⇒ fx source missing in OBS.
- **fal.ai**: FAL key starts lowercase `c` (phone auto-capitalize bit us). Queue poll URLs MUST come from submit response (nested model ids break constructed URLs). Effect gens need "isolated on pure black, no text" + negative_prompt; a global brand prefix hijacks them (now opt-in `brand:true`). stable-audio/Kling take 1-5min — always queue via submit/poll, never inline.
- **Reframe crop**: `crop{x,y,z}` needs a CLIPPING ancestor or a zoom spills instead of cropping — FX one-shots/stingers render inside `.fxbox` (owns geometry + overflow:hidden), the media just fills it. A running `@keyframes` outranks an inline `transform`, so the still-image pop takes the zoom as `--rfz` and MULTIPLIES it in rather than being overwritten. Clamp is 600% in overlay AND panel (they disagreed: panel 600, overlay 400). Board backgrounds and button textures crop too: a still board bg is a real `<img>` in a clipping wrapper (`makeStill`), and a button texture uses `--btnzoom`/`--btnpan` (background-size/position) since there is no per-cell element. **`applyBoardParts` change key MUST include both crops** — it early-returns on an unchanged key, so a crop-only edit silently did nothing no matter what the render path could do. `qa/shoot-fx-crop.mjs`.
- **Banner transition is a SLIDE, not a fade**: `#banners` is a filmstrip — the incoming `.b` waits at `translateX(-100%)`, `.live` brings it to 0 and `.out` sends the previous one to `+100%`, so the pair tiles edge to edge with no overlap and no gap (`#banners` is `overflow:hidden`, which is what hides both off-canvas halves). Two hazards the old crossfade masked: (1) **both halves must start in the same frame** — the old code added `.live` after a double rAF but un-`live`d the previous banner synchronously, invisible with opacity, a sliver of empty band with a slide; (2) **a one-banner rotation re-renders itself every cycle**, which is invisible when you dissolve an image into an identical copy and obvious when you scroll it, so `shownId` makes a lone banner hold. `meta.crop` is inline on the inner `img`/`video` while the slide transform is on the `.b` wrapper — they never collide. `qa/shoot-banner-slide.mjs` (offline; detect motion by POSITION, not by `.live`/`.out` — both classes persist after the transition ends, and `.live` names the OLD banner in the frame before the slide starts).
- **"Stuttery" was never dropped frames**: 26s of live rAF sampling measured 16.7ms median with ZERO dropped vsyncs, before and after. Two other things read as jank. (1) **A dead file restarted the slide mid-travel** — the old order appended, slid, then discovered the 404 via `onerror` and started over (recorded x path `-1080 -997 -915` then snapping back to `-1080`). Banners are now built OFF-canvas and slide only after `mediaReady()` resolves (`img.decode()` covers fetch+decode in one wait, 4s timeout, then skip to the next candidate) — a `gen` counter drops an in-flight build if the rotation changes underneath it. (2) **Front-loaded easing**: the first cut opened at 83px/frame and crawled the last 150px at 1-2px/frame. Now easeInOutSine (`cubic-bezier(.37,0,.63,1)`) over 800ms — measured peak 36px/frame, opening step 1px, a symmetric bell. When judging motion, measure the per-frame px STEPS, not the frame gaps: perfect pacing and horrible motion look identical in a frame-time histogram. Separately, the OBS sources at `scale=(1.001,1.000)` resample every frame, which costs far more on MOVING content than on a static board — see backlog item 1.
- **EGRESS: `display:none` does not stop a fetch**. Each PC runs three browser sources and layer selection is only CSS, so ungated, every source downloads every asset. Measured before gating: the SAME background webm pulled by all three sources, 14.4 MB each, on every load. `setBackground`, the board background/button texture/button-anim clips, the 32 cell logos and the banner rotator are gated on `BG_LAYER`/`HUD_LAYER` — **gate the FETCH, never the bookkeeping**: `applyState`/`applyBoardParts` must still run identically on all three or `pendingDim`, `partsKey` and the highlight logic drift per source. Per-PC reload cost went 43 MB -> 14.4 MB. `qa/shoot-egress.mjs` guards it, and asserts BOTH directions — hud/fx pull zero background AND bg still pulls its own (over-gating is the easy regression).
- **EGRESS: measure with CDP, never `page.on("response")`** — response events fire for CACHE HITS too, carrying the full `content-length`. That reports a primed reload as 32 MB when it truly costs 0, and produced a confidently wrong "384 MB per reload" mid-investigation. Only `Network.loadingFinished.encodedDataLength` is bytes on the wire. Equally, probe cache headers with GET: **HEAD returns `no-cache` regardless** of the stored value and will send you chasing a header problem that does not exist.
- **EGRESS: the browser cache-size cliff is what actually matters**, not `max-age`. Bracketed: 3.3 MB caches, 12.8 MB caches, 15.8 MB does not. So a 6 MB stinger is free after first load while a 15.8 MB background re-downloads forever — and `team_anim` at 16-36 MB/clip is over the cliff on every clip. A STALE cached video revalidates with a free 304 (measured), so raising `max-age` from 1 hour to 1 year saves conditional requests, not megabytes; all 238 objects now sit at a year via `storage.objects.metadata`, but note a metadata-only SQL patch does NOT purge Cloudflare, so the wire keeps the old header until the edge entry expires. **Shrinking a file below the cliff is worth more than any header.**
- **EGRESS: realtime and thumbnails.** `stream_state` is subscribed with `filter:id=eq.<pc>`; unfiltered, all 15 sources got all 5 PCs' state and discarded 14/15. `events` CANNOT be filtered that way — it is `(id,type,payload,created_at)` with the pc inside the jsonb, and realtime filters only work on real columns. Control-page thumbnails go through `/storage/v1/render/image/public/...?width=240&quality=60`; a 78px card was pulling the 2 MB source PNG, which was nearly all of the 15.8 MB it cost to open a dashboard (now 3.45 MB). Restrict the rewrite to png/jpg/webp — an unsupported format 4xxs and trips the "file missing" chip on a healthy file.
- **Board scale**: `boardGap` -20..20 — CSS `gap` cannot be negative, so overlap shrinks the grid TRACK below `--tile` and lets each cell overflow its own track by |gap|; positive spacing still uses a real `gap`. `boardSize` 40-150 (>100 hands back the board padding so nothing crops to ~127%; past that the outer teams go off-canvas, accepted). `logoSize` 60-200 (>100 drives `--logofrac` NEGATIVE so the logo spills; needs `#board.logo-spill` to drop `.cell{overflow:hidden}`). Any per-grid `--logopad` override MUST be expressed as an offset from `var(--logofrac)` or the Logo slider silently dies on that grid. `fxIntensity` scales brightness/size ONLY — never divide an animation duration by it.
- **The bg/board seam gradient** (`#bgFrame .fade`) is a SMOOTHSTEP, not a linear ramp. A 2-stop `linear-gradient(transparent, rgba(...))` darkens at a constant rate, and the slope discontinuity where it begins reads as a hard line over the artwork (Mach banding) — measured, the old 70px version veiled the background from y=418 down. Now 44px with smoothstep stops: gentle at BOTH ends, steepest in the middle where the eye cannot localise an edge, so the onset only appears at y=445 and it eases into the board rather than slamming. Judge it by measuring per-row luminance over a flat white `#bgFrame` (screenshot, then `ffmpeg -vf scale=1:100 -pix_fmt gray`), never by eye: the numbers that matter are where darkening first becomes visible and the steepest single-row step. Shortening the run necessarily steepens it somewhere — put that steepness at the bottom, against the hard edge of the board, where it is masked.
- **Button layers (v5)**: a cell stacks `img.tex` (button style fill, z0) → `div.frm` (button frame, z1) → `img.logo` (z2) → `.vfx` (z5). The texture uses **object-fit:cover** — the old `background-size:100% 100%` STRETCHED art to the cell box and warped every non-square grid. The frame CANNOT use cover: cropping a square frame into rect84's wide cells throws away the top and bottom rails, so it is **9-sliced** (`border-image`, no `fill` keyword so the middle stays see-through). Each frame carries its own `meta.sliceFrac`; `--frmw` is that fraction of the CELL's short side, measured from the DOM because rect84 stretches its tracks and `--tile` reads `auto` there. Honeycomb and slant hide frames outright — a rectangular 9-slice cannot follow a hexagon. In `setCellLayer`, skip-guard only the SRC; the crop must reapply every call or a crop-only edit silently does nothing (the same early-return trap as `applyBoardParts`' change key).
- **The builtins are split, and null ≠ undefined**: "Gold Buttons" used to weld a copper bezel to a teal fill, which is why the radial darkening could not be switched off. Now `.frame-gold` and `.btn-teal` are independent, with "Teal Glass (default fill)" under `board_button` and "No Button Frame" / "Gold Bezel" under `button_frame`. The panels' Apply handler stores **null for any builtin with no `effect`**, so a frame builtin that should mean "off" must be effect-less and one that should render must carry an effect. `boardFrame === undefined` means "keep what this board had" (bezel only if it had no custom texture); an explicit `null` means off. Every PC has it written explicitly so panel and overlay cannot disagree. `qa/shoot-button-layers.mjs`.
- **A vignette in the artwork is not a CSS bug**: the "radial gradient darkening each button" report was two different things — the welded builtin on the boards using it, and, on a board wearing a custom texture, a vignette baked into the PNG (Tile_3.png measures 146 luminance at centre against 25 at the corners). Sample a 9x9 luminance grid before hunting for CSS. `scripts/extract-button-frame.mjs` splits an artwork into frame + fill: flood-fill the interior from the centre using the bright inner border as the wall (a square crop cannot follow a rounded bevel), and take the button bbox at near-full alpha so the feathered drop shadow is excluded.
- **"Grainy on stream" is NOT the overlay**: measured end to end. A 1:1 capture of the live board magnified with nearest-neighbour is clean, and the 905px team logos downscaling into a ~37px box are indistinguishable from Lanczos-prescaled 256px/128px copies, so Chromium is doing that reduction well and pre-scaling the logos buys nothing. The damage is downstream: `AC_Breakz.json` has all three browser sources at the correct 1080x1920 but every scene item at `scale=(1.00082302, 1.0)` — a HORIZONTAL-ONLY 0.08% stretch, so each pixel column is a blend of two neighbours at a shifting phase while rows stay sharp. That asymmetry is what reads as grain on logo edges and bevels, and it costs encoder bitrate too. Check the scene collection before touching any rendering code.
- **A panel left open writes STALE assets**: per-PC state stores a COPY of the asset row, and both control pages cache their asset list at load. A panel open across a re-upload therefore writes the OLD url back onto a board on the next Apply, silently undoing the update — that is how a replaced button frame came back, and `lastWriter` being a browser client id rather than a script is what proves it. Both Apply handlers now re-read the row by id at click time (master guards on `sb`, which is null in offline preview). After ANY asset re-upload, resync the per-PC copies; updating the assets table alone changes nothing on screen.
- **Glow is a rim, not a halo**: two stacked drop-shadows at 1.6px and 3.2px on a ~37px logo read as BLUR and were reported as "grainy". One sub-pixel rim (0.015 of the cell) separates the logo without softening it. Judge effects like this at 6x nearest-neighbour magnification against the previous build — at 1:1 the difference is invisible, and on stream it just looks like bad encoding.
- **A new per-PC selection key must be added in THREE places**: the overlay, `assets_deselect` (the slot list inside it), and `scripts/audit-refs.mjs`. `boardFrame` was added to the overlay only, so purging a button frame deleted the file (purge is reference-counted) and the row while leaving every board still pointing at it — the overlay then rendered `border-image` with nothing to load and fell back to `border-color: currentColor`, i.e. a BLACK border. The audit reported "no dangling references" the whole time because it did not know the key either. `supabase/migrate-v14-boardframe.sql`. Symptom to remember: a frame that renders solid black is a missing image, not a styling problem — probe the rendered pixels and then GET the url.
- **An upload that reports success is not proof**: `uploadToSignedUrl` returning no error does not mean the object is in the bucket. `scripts/repair-button-frame.mjs` is the pattern — upload, confirm the name AND byte size against the BUCKET LISTING, then GET the public url expecting 200/206, and only then repoint any row or per-PC copy.
- **An outward glow can only come from the CELL itself**: `overflow:hidden` clips a cell's DESCENDANTS, not the cell's own `box-shadow` — so no inner element can ever light the outside, which is why every attempt to build the glow inside `.cell` produced flat colour. The glow is now a box-shadow on `.cell.hl`: an inset tint on the frame plus outward bleed, with `z-index:6` so a neighbouring tile cannot paint over it. `clip-path` DOES cut a box-shadow (unlike overflow), so honeycomb/slant keep an inner ring instead — an outward glow around a hexagon is not expressible and should not be faked. Two colours: `glowColor` tints the frame, `glowLight` spills, and `glowLight` defaults to `glowColor` so they blend by default. Alphas are pre-mixed in JS into `--glowc-a/-b`/`--glowl-a/-b` — `color-mix()` needs a newer engine than some OBS CEF builds ship. Corner radius is **.165 of the tile**, measured off the frame artwork with `scripts/measure-corner.mjs` (the top row of a rounded rect runs x0+r..x1-r, so the first opaque pixel's inset IS the radius), not guessed.
- **Glow is light, and `filter` applies BEFORE `clip-path`**: put the shape and the glow on one element and the bleed is clipped away, leaving flat colour — which is exactly how the edge glow lost its glow. The ring is an inner `<i>`; the drop-shadows live on its parent `.edge`. The cell clips children, so the outward bleed is trimmed and what reads on screen is light spilling INWARD. Corner shape comes from `--radius` (checker = 0 = hard corners), never a hard-coded radius. Glow colour is `state.glowColor` -> `--glowc`, regex-validated before it reaches a custom property. ## 4. ACCUMULATED NUANCES & NEVER-DO RULES

- **VP9 alpha is side-channel**: ffprobe says `yuv420p` even with alpha. Decode `-c:v libvpx-vp9` (input opt), encode `-pix_fmt yuva420p -auto-alt-ref 0`, fade `fade=t=out:…:alpha=1`. M3 lost alpha this way (black bg bug). Current stingers `animations/v2/`, cropped one-shots `animations/v4/`; old flat files unreferenced.
- **API Ninja**: empty-string file fields → NullReference in `LoadHeadersAndUserData` → EVERY request dies (⚠). Must be `"No file..."`. `autorunMinutes:"0"` = fire-every-0-min crash loop; empty = off. Multi Action ✓ ≠ plugin success. Its plugin manifest is ENCRYPTED — read `PropertyInspector/*.html/js`, the DLL strings, or diff a hand-made exported button (fastest, do this FIRST next time).
- **Stream Deck**: profiles live in `ProfilesV3` (not V2). Import DUPLICATES (delete old first). PowerShell/.NET zip writes backslash entries → silent import failure. `PageIndex` 1-based. `system.open` = files only; URLs need `system.website` `{openInBrowser:true,path}`. Icons are per-key press-state only (can't track board; accepted cosmetic drift). Icon art: `streamdeck/icons/*`.
- **Write model (V11 — replaces the old "echo clock" rule)**: `data.board` is written ONLY by `board_action()`; every other top-level key ONLY by `state_patch()`/`state_replace()` (`supabase/migrate-v11-atomic.sql`, applied). All three `select … for update` the row and lock PCs in ASCENDING id order (deadlock-free). That row lock IS the queue — an app-level queue was rejected: a dead worker returns 200 for a press that never applied. NEVER do I/O while holding the lock — the edge fns pre-resolve stinger/sfx assets and pass them as `p_fx`. The FX event inserts in the SAME transaction and only on a real transition, so a stinger cannot play for an elimination that did not record (pre-fix, measured: 12 stingers fired, 1 recorded; 12 simultaneous presses landed 1). `updatedAt`/`lastWriter` are stamped in ONE place (`state_stamp`, Postgres `clock_timestamp()`); pages suppress their own echo by `lastWriter === CLIENT_ID` and drop out-of-order realtime by `updatedAt < current` — that comparison is valid ONLY because of the single clock; the old browser-vs-edge one silently dropped real writes and then re-pushed over them. Each page keeps ONE write in flight and coalesces pending patches (concurrent same-key patches otherwise land out of order). Anon must stay denied on all three RPCs (grants are service_role only). `qa/shoot-concurrency.mjs` + `qa/shoot-panel-race.mjs` guard it; the old "panel writes first, 1.2-1.5s apart" QA rule is retired.
- **Write model (V13 — the asset writers)**: `deselectEverywhere` and `update_asset` propagation were the last read-whole-doc→write-whole-doc writers, and they were NOT harmless: reached by delete/purge/empty_trash/hideRotation and the Reframe **Save crop** button — all routine mid-show actions — each read five rows and wrote them back unlocked, erasing any press that landed mid-loop *after* the API had returned OK and the stinger had played. Now `assets_deselect()` / `assets_propagate_meta()` (`supabase/migrate-v13-asset-writes.sql`, applied): loop `1..5 order by id`, `select … for update`, and mutate ONLY `banners.rotation`/`background`/`animStyle`/`boardButtons`/`boardBg`/`buttonAnim`/`buttonAnims` via `jsonb_set` — being field-scoped makes them structurally incapable of touching `board`, `loopFx` or `oneshots`. Rotation order is preserved with `with ordinality`. **Five decks pressed at once were always safe** (separate rows, separate locks); it was master-panel asset work that broke them. `qa/shoot-multipc.mjs` proves it — and note a race test that fires ONCE proves nothing: its first run passed, and only starting the sweep first and repeating 8 rounds exposed the bug (lost in 8/8).
- **Never hold a lock for housekeeping**: `board_action`'s inserts into `events`/`deck_log` used to fire statement triggers that DELETEd expired rows — which are GLOBAL, not per-PC — so a five-PC master tap and a single-PC deck press could deadlock. Triggers dropped; the deck fn calls `prune_now()` opportunistically (~2% of calls) AFTER the RPC returns, unawaited via `EdgeRuntime.waitUntil`. It must `returns int`, never `returns void`: PostgREST answers a void RPC with **204 + empty body**, which `.json()` throws on outside the `.catch()` — measured 4/200 deck calls failing until it returned a value (0/250 after).
- **Restart ≠ rebuild**: to restart a playing `<video>`, SEEK it (`currentTime=0;play()`). Removing/recreating the element drops to readyState 0 → blank frame until re-buffer + one refetch per cell per change (v10 bug: "any change kills the button animations" — only bit the AI-clip path, CSS builtins restart free, so v9's acceptance missed it). New elements need `autoplay:true` — no blanket play() loop exists anymore. QA that frame-samples races the CDN cache and can pass on broken code; assert on element identity (dataset tags surviving) + refetch counts instead.
- **Master/PC list parity**: any list rendered in BOTH `control/index.html` and `control/pc.html` must use the IDENTICAL filter — the dashboards have no delete, so anything they list that master doesn't is unremovable (pc.html listed `kind:"background"` as composer art long after master narrowed to banner-only ⇒ 9 undeletable cards). Composer membership = `inComposer()` in master: `url && kind==="banner" && meta.type!=="text"`, minus `hideComposer`. These lists derive from the shared `assets` row, NOT per-PC state — there is nothing to migrate, fixing the predicate syncs all five instantly. `qa/shoot-composer-sync.mjs` guards it.
- **Deletion**: every removal path (delete/purge/empty_trash/hideRotation) MUST `deselectEverywhere` or OBS shows blank frames. Rotator also skips missing files via `onerror`. Purge is REFERENCE-COUNTED (`unreferencedFiles` in panel fn): "file into section" makes a second row pointing at the SAME storage file, so a file is only removed when no surviving row's url/base_url/button_url/bg_url/poster/sfxUrl points at it — before this, purging the original deleted the file under the filed copy (lost 2 AI clips 2026-08-11). `qa/shoot-purge-refs.mjs` proves it; judge storage existence by BUCKET LISTING, the public URL serves CDN-cached 200s long after deletion (also why a dead file can keep "working" in an open overlay).
- **Cold start is the "it didn't play the first time" bug**: nothing preloaded FX media and the overlay doesn't even learn a stinger URL until the press event arrives, so a first press was a cold fetch of a ~6 MB clip (205 MB for the set, and `upload-v2.mjs` never set `Cache-Control`, so it was served `no-cache`). Which teams "showed" tracked purely which clips happened to be cache-warm — that is the same bug as "sound plays, stinger doesn't, for some teams only". The overlay now warms the resolved set on load and whenever `animStyle.meta.set`/`oneshots` change, via throwaway `<video preload=auto>` elements it then removes (bytes stay in the HTTP cache, decoders do not). - **`playVideo` must be able to give up**: it used to exit only on `ended`/`error`/rejected `play()`, so a hung buffer pinned `fxBusy` and wedged the whole FX queue until reload. QA cannot catch that path: Playwright runs with `--autoplay-policy=no-user-gesture-required`.
- **Realtime delivers the state row BEFORE its event**: `board_action` writes `stream_state` and inserts `events` in ONE transaction, and the row always arrives first (measured ~630ms vs ~700ms). So anything the event handler wants to choreograph must be deferred by `applyState`, not by the handler — parking the team in `pendingDim` from `handleEvent` was always too late, the cell had already been painted. `applyState` now parks any not-out→out transition itself and arms a 900ms fallback; `team_pick` takes that fallback over and re-arms 1200ms from the video's `playing` event (2600ms cap), so the board never dims before the stinger exists. `boardBooted` keeps the FIRST paint immediate — a page load is not a transition. Restores/resets must `clearDim` every timer the team is owed, and must NOT re-run `applyState` from the handler: `lastState` still says the team is out, so it would arm a fresh dim for the team just put back.
- **A dangling reference is invisible until you look for it**: `assets_deselect` only runs when a row is deleted THROUGH the panel, so a row purged before V13 (or by a direct DB edit) leaves its entry alive inside every PC's `banners.rotation`/selection with no row left to clean up. ## 4. ACCUMULATED NUANCES & NEVER-DO RULES

- **VP9 alpha is side-channel**: ffprobe says `yuv420p` even with alpha. Decode `-c:v libvpx-vp9` (input opt), encode `-pix_fmt yuva420p -auto-alt-ref 0`, fade `fade=t=out:…:alpha=1`. M3 lost alpha this way (black bg bug). Current stingers `animations/v2/`, cropped one-shots `animations/v4/`; old flat files unreferenced.
- **API Ninja**: empty-string file fields → NullReference in `LoadHeadersAndUserData` → EVERY request dies (⚠). Must be `"No file..."`. `autorunMinutes:"0"` = fire-every-0-min crash loop; empty = off. Multi Action ✓ ≠ plugin success. Its plugin manifest is ENCRYPTED — read `PropertyInspector/*.html/js`, the DLL strings, or diff a hand-made exported button (fastest, do this FIRST next time).
- **Stream Deck**: profiles live in `ProfilesV3` (not V2). Import DUPLICATES (delete old first). PowerShell/.NET zip writes backslash entries → silent import failure. `PageIndex` 1-based. `system.open` = files only; URLs need `system.website` `{openInBrowser:true,path}`. Icons are per-key press-state only (can't track board; accepted cosmetic drift). Icon art: `streamdeck/icons/*`.
- **Write model (V11 — replaces the old "echo clock" rule)**: `data.board` is written ONLY by `board_action()`; every other top-level key ONLY by `state_patch()`/`state_replace()` (`supabase/migrate-v11-atomic.sql`, applied). All three `select … for update` the row and lock PCs in ASCENDING id order (deadlock-free). That row lock IS the queue — an app-level queue was rejected: a dead worker returns 200 for a press that never applied. NEVER do I/O while holding the lock — the edge fns pre-resolve stinger/sfx assets and pass them as `p_fx`. The FX event inserts in the SAME transaction and only on a real transition, so a stinger cannot play for an elimination that did not record (pre-fix, measured: 12 stingers fired, 1 recorded; 12 simultaneous presses landed 1). `updatedAt`/`lastWriter` are stamped in ONE place (`state_stamp`, Postgres `clock_timestamp()`); pages suppress their own echo by `lastWriter === CLIENT_ID` and drop out-of-order realtime by `updatedAt < current` — that comparison is valid ONLY because of the single clock; the old browser-vs-edge one silently dropped real writes and then re-pushed over them. Each page keeps ONE write in flight and coalesces pending patches (concurrent same-key patches otherwise land out of order). Anon must stay denied on all three RPCs (grants are service_role only). `qa/shoot-concurrency.mjs` + `qa/shoot-panel-race.mjs` guard it; the old "panel writes first, 1.2-1.5s apart" QA rule is retired.
- **Write model (V13 — the asset writers)**: `deselectEverywhere` and `update_asset` propagation were the last read-whole-doc→write-whole-doc writers, and they were NOT harmless: reached by delete/purge/empty_trash/hideRotation and the Reframe **Save crop** button — all routine mid-show actions — each read five rows and wrote them back unlocked, erasing any press that landed mid-loop *after* the API had returned OK and the stinger had played. Now `assets_deselect()` / `assets_propagate_meta()` (`supabase/migrate-v13-asset-writes.sql`, applied): loop `1..5 order by id`, `select … for update`, and mutate ONLY `banners.rotation`/`background`/`animStyle`/`boardButtons`/`boardBg`/`buttonAnim`/`buttonAnims` via `jsonb_set` — being field-scoped makes them structurally incapable of touching `board`, `loopFx` or `oneshots`. Rotation order is preserved with `with ordinality`. **Five decks pressed at once were always safe** (separate rows, separate locks); it was master-panel asset work that broke them. `qa/shoot-multipc.mjs` proves it — and note a race test that fires ONCE proves nothing: its first run passed, and only starting the sweep first and repeating 8 rounds exposed the bug (lost in 8/8).
- **Never hold a lock for housekeeping**: `board_action`'s inserts into `events`/`deck_log` used to fire statement triggers that DELETEd expired rows — which are GLOBAL, not per-PC — so a five-PC master tap and a single-PC deck press could deadlock. Triggers dropped; the deck fn calls `prune_now()` opportunistically (~2% of calls) AFTER the RPC returns, unawaited via `EdgeRuntime.waitUntil`. It must `returns int`, never `returns void`: PostgREST answers a void RPC with **204 + empty body**, which `.json()` throws on outside the `.catch()` — measured 4/200 deck calls failing until it returned a value (0/250 after).
- **Restart ≠ rebuild**: to restart a playing `<video>`, SEEK it (`currentTime=0;play()`). Removing/recreating the element drops to readyState 0 → blank frame until re-buffer + one refetch per cell per change (v10 bug: "any change kills the button animations" — only bit the AI-clip path, CSS builtins restart free, so v9's acceptance missed it). New elements need `autoplay:true` — no blanket play() loop exists anymore. QA that frame-samples races the CDN cache and can pass on broken code; assert on element identity (dataset tags surviving) + refetch counts instead.
- **Master/PC list parity**: any list rendered in BOTH `control/index.html` and `control/pc.html` must use the IDENTICAL filter — the dashboards have no delete, so anything they list that master doesn't is unremovable (pc.html listed `kind:"background"` as composer art long after master narrowed to banner-only ⇒ 9 undeletable cards). Composer membership = `inComposer()` in master: `url && kind==="banner" && meta.type!=="text"`, minus `hideComposer`. These lists derive from the shared `assets` row, NOT per-PC state — there is nothing to migrate, fixing the predicate syncs all five instantly. `qa/shoot-composer-sync.mjs` guards it.
- **Deletion**: every removal path (delete/purge/empty_trash/hideRotation) MUST `deselectEverywhere` or OBS shows blank frames. Rotator also skips missing files via `onerror`. Purge is REFERENCE-COUNTED (`unreferencedFiles` in panel fn): "file into section" makes a second row pointing at the SAME storage file, so a file is only removed when no surviving row's url/base_url/button_url/bg_url/poster/sfxUrl points at it — before this, purging the original deleted the file under the filed copy (lost 2 AI clips 2026-08-11). `qa/shoot-purge-refs.mjs` proves it; judge storage existence by BUCKET LISTING, the public URL serves CDN-cached 200s long after deletion (also why a dead file can keep "working" in an open overlay).
- **Cold start is the "it didn't play the first time" bug**: nothing preloaded FX media and the overlay doesn't even learn a stinger URL until the press event arrives, so a first press was a cold fetch of a ~6 MB clip (205 MB for the set, and `upload-v2.mjs` never set `Cache-Control`, so it was served `no-cache`). Which teams "showed" tracked purely which clips happened to be cache-warm — that is the same bug as "sound plays, stinger doesn't, for some teams only". The overlay now warms the resolved set on load and whenever `animStyle.meta.set`/`oneshots` change, via throwaway `<video preload=auto>` elements it then removes (bytes stay in the HTTP cache, decoders do not). Two non-optional constraints: **gate on `layer==="fx"||"all"`** (each PC runs three browser sources — ungated, every PC pulls the set 3× = 615 MB) and **cap concurrency at 3** (32 parallel 6 MB fetches at OBS start spike the same uplink the stream goes out on). New uploads set `cacheControl:"31536000"`. `qa/shoot-fx-warm.mjs` asserts 30+ clips on `layer=fx` and exactly 0 on `layer=hud` — and its two counting passes `route()`+`abort()` the clip bodies, because they only ever needed the URLs and were costing ~250 MB of real egress per run. The warmed bytes DO survive a reload (measured 239 MB cold -> 0 MB on reload) but only because those clips are under the browser's cache-size cliff; see the egress rules below.
- **`playVideo` must be able to give up**: it used to exit only on `ended`/`error`/rejected `play()`, so a hung buffer pinned `fxBusy` and wedged the whole FX queue until reload. It now has an 8s watchdog, and on a rejected `play()` it retries MUTED — the graphic matters more than its audio, and team stingers are `-an` but the game one-shots carry Opus. QA cannot catch that path: Playwright runs with `--autoplay-policy=no-user-gesture-required`.
- **Realtime delivers the state row BEFORE its event**: `board_action` writes `stream_state` and inserts `events` in ONE transaction, and the row always arrives first (measured ~630ms vs ~700ms). So anything the event handler wants to choreograph must be deferred by `applyState`, not by the handler — parking the team in `pendingDim` from `handleEvent` was always too late, the cell had already been painted. `applyState` now parks any not-out→out transition itself and arms a 900ms fallback; `team_pick` takes that fallback over and re-arms 1200ms from the video's `playing` event (2600ms cap), so the board never dims before the stinger exists. `boardBooted` keeps the FIRST paint immediate — a page load is not a transition. Restores/resets must `clearDim` every timer the team is owed, and must NOT re-run `applyState` from the handler: `lastState` still says the team is out, so it would arm a fresh dim for the team just put back.
- **A dangling reference is invisible until you look for it**: `assets_deselect` only runs when a row is deleted THROUGH the panel, so a row purged before V13 (or by a direct DB edit) leaves its entry alive inside every PC's `banners.rotation`/selection with no row left to clean up. One such orphan — a banner whose row was hard-purged in the pre-reference-counting era — sat in all five rotations and generated **~330 HTTP 400s an hour, 8,765 in 48h, 87% of ALL Supabase requests**, for weeks, in complete silence. `scripts/audit-refs.mjs` is the detector: it cross-checks every url/base_url/button_url/bg_url/poster/sfxUrl on every asset row AND every per-PC selection against the BUCKET LISTING (never the public URL — the CDN serves cached 200s long after a delete), exits non-zero on findings, and `--fix` deselects through the row-locked `assets_deselect`. Run it after any purge and whenever something "works but shouldn't". It is also how you check the backlog's "dead asset" claims instead of trusting them.
- **Never re-ask for media that already failed**: the rotator keeps a `deadMedia` Set and skips a known-bad url WITHOUT building an element, so a dangling reference costs ONE request per session instead of one per rotation cycle per source, forever. A replaced file always arrives under a new timestamped url, so nothing legitimate is blocked, and a reload clears the set anyway. `qa/shoot-banner-slide.mjs` asserts the dead url is requested at most once.
- **Never destructure only `data` from a PostgREST call**: every lookup in the deck fn did `const { data } = await q`, dropping `error`. PostgREST returned a transient **401 to the service-role client 16 times in 48h**, and each one made `teamClipUrl` return null — so the press eliminated the team and played its sfx with NO stinger. That is indistinguishable from a missing clip, which is exactly why it hid behind the cold-media bug for so long. All five lookups now go through `q1()`: retry once, then `console.error` loudly so it lands in the function logs. Check `function_edge_logs`/`edge_logs` for 401s when a stinger "sometimes" does not play.
- **Audio**: keep `Audio` refs in a Set until ended (GC aborts request); only `layer=fx`/`all` plays sound — "sound but no stinger" ⇒ fx source missing in OBS.

Clamp is 600% in overlay AND panel (they disagreed: panel 600, overlay 400). Board backgrounds and button textures crop too: a still board bg is a real `<img>` in a clipping wrapper (`makeStill`), and a button texture uses `--btnzoom`/`--btnpan` (background-size/position) since there is no per-cell element. **`applyBoardParts` change key MUST include both crops** — it early-returns on an unchanged key, so a crop-only edit silently did nothing no matter what the render path could do. `qa/shoot-fx-crop.mjs`.
- **Banner transition is a SLIDE, not a fade**: `#banners` is a filmstrip — the incoming `.b` waits at `translateX(-100%)`, `.live` brings it to 0 and `.out` sends the previous one to `+100%`, so the pair tiles edge to edge with no overlap and no gap (`#banners` is `overflow:hidden`, which is what hides both off-canvas halves). Two hazards the old crossfade masked: (1) **both halves must start in the same frame** — the old code added `.live` after a double rAF but un-`live`d the previous banner synchronously, invisible with opacity, a sliver of empty band with a slide; (2) **a one-banner rotation re-renders itself every cycle**, which is invisible when you dissolve an image into an identical copy and obvious when you scroll it, so `shownId` makes a lone banner hold. `meta.crop` is inline on the inner `img`/`video` while the slide transform is on the `.b` wrapper — they never collide. `qa/shoot-banner-slide.mjs` (offline; detect motion by POSITION, not by `.live`/`.out` — both classes persist after the transition ends, and `.live` names the OLD banner in the frame before the slide starts).

Separately, the OBS sources at `scale=(1.001,1.000)` resample every frame, which costs far more on MOVING content than on a static board — see backlog item 1.

Only `Network.loadingFinished.encodedDataLength` is bytes on the wire. So a 6 MB stinger is free after first load while a 15.8 MB background re-downloads forever — and `team_anim` at 16-36 MB/clip is over the cliff on every clip. Restrict the rewrite to png/jpg/webp — an unsupported format 4xxs and trips the "file missing" chip on a healthy file.
- **Board scale**: `boardGap` -20..20 — CSS `gap` cannot be negative, so overlap shrinks the grid TRACK below `--tile` and lets each cell overflow its own track by |gap|; positive spacing still uses a real `gap`. `boardSize` 40-150 (>100 hands back the board padding so nothing crops to ~127%; past that the outer teams go off-canvas, accepted). `logoSize` 60-200 (>100 drives `--logofrac` NEGATIVE so the logo spills; needs `#board.logo-spill` to drop `.cell{overflow:hidden}`). - **The bg/board seam gradient** (`#bgFrame .fade`) is a SMOOTHSTEP, not a linear ramp. A 2-stop `linear-gradient(transparent, rgba(...))` darkens at a constant rate, and the slope discontinuity where it begins reads as a hard line over the artwork (Mach banding) — measured, the old 70px version veiled the background from y=418 down. Now 44px with smoothstep stops: gentle at BOTH ends, steepest in the middle where the eye cannot localise an edge, so the onset only appears at y=445 and it eases into the board rather than slamming. That asymmetry is what reads as grain on logo edges and bevels, and it costs encoder bitrate too. Check the scene collection before touching any rendering code.

A panel open across a re-upload therefore writes the OLD url back onto a board on the next Apply, silently undoing the update — that is how a replaced button frame came back, and `lastWriter` being a browser client id rather than a script is what proves it. Both Apply handlers now re-read the row by id at click time (master guards on `sb`, which is null in offline preview). After ANY asset re-upload, resync the per-PC copies; updating the assets table alone changes nothing on screen.
- **Glow is a rim, not a halo**: two stacked drop-shadows at 1.6px and 3.2px on a ~37px logo read as BLUR and were reported as "grainy". One sub-pixel rim (0.015 of the cell) separates the logo without softening it.
